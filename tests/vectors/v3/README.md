# v3 golden vectors

Contract for the v3 engine specified in
[ADR-0009](../../../docs/adr/0009-v3-key-stretching-and-derivation.md). Same rules as the v1
file one directory up: **Python is normative**, a failure is never "fix the test", and
regenerating is a compatibility break.

```bash
python tools/generate_vectors_v3.py            # rewrite
python tools/generate_vectors_v3.py --check    # fail if stale (CI)
```

| File | Pins |
|---|---|
| `canonical.json` | §1: canonical form of every input, with the inputs that must be **rejected** |
| `derivation.json` | §2–§5: encoding, Argon2id, extract, every HKDF purpose, password sampling |

## What a port must get right

**Rejections are part of the contract.** A case marked `"reject": true` must fail in every
implementation. Accepting an input Python rejects creates a password only that port can derive.

**Only ASCII letters are lowered**, and whitespace is the explicit code point list in
`canonical.json`, not the platform's idea of whitespace.

**Three full-cost Argon2id cases, the rest starts from `fixed_k0_hex`.** A port runs 256 MiB
three times, not once per case. `argon2_password_hex` and `argon2_salt_hex` are the exact
Argon2id inputs, so a mismatch localises to encoding or to the KDF.

**Sampling reads unsigned bytes.** `byte_rejections`, `candidate_rejections` and
`stream_bytes_used` record how far each case went; a port that agrees on the password but not
on these numbers is consuming the stream differently and will diverge on another input.

**A rejected candidate does not restart the stream.** The next candidate continues from the
current position.

## Checks that do not come from this code

Vectors generated by an implementation cannot show that the implementation is right. Those
checks live in `tests/test_v3_derive.py`: Argon2id against a second implementation (OpenSSL,
via `cryptography`) which is itself anchored to the RFC 9106 test vector, HKDF-SHA512 against
`../third_party/wycheproof/`, and a chi-square test of the sampler.
